# Roland SP-404MKII

**Files:** `Cut It/m_404.pd` · **Gate:** `test/gate/sp404-assert.sh` · **Bench:** `test/bench/midi-bench.pd`

## What it is

**The rig's sampler, and the only bidirectional device in it** — every other `m_` layer either only
listens (nano, Launchpad, Organelle) or only speaks (Volca). What the SP-404MKII is — its addressing,
pad map, MIDI, clock behavior, settings and traps — is in Reference:
`~/Sites/!reference/roland-sp-404mkii.md`. This page is how Cut It uses it.

It is addressed as **160 pads, not 16**. `m_404.pd` is the only file allowed to talk to it, and it
owns the device's panic across all ten channels.

It also carries the rig's audio: drums hard-panned left and fx hard-panned right, giving two
independent mono streams out of one stereo pair.

Pd device 3 owns channels 33–48; the ten banks use 33–42 and leave 43–48 unused.

`m_404`'s creation argument is the Pd channel that bank A lands on — **33**. There is no second
argument for the output port: `noteout`'s channel encodes it, so 33 reaches slot 3 exactly as 49
reaches slot 4.

### What `m_404` publishes, and one pad hit is ONE row on the OLED

**`m_404` publishes on `param` alone, and the row a hit draws is `u_map`'s** — the same mechanism
that makes `slider-3` and `pad-43` name themselves (item 317).

| On | Name | Built by | Evidence | Item |
|---|---|---|---|---|
| `param` | `sp-a1` … `sp-j16` — the bank letter and the pad number. The release too, at velocity 0 | `m_404`, `[makefilename sp-a%d]` and ten literal `set` boxes | verified | 283 |
| `param` | `sp-cc-16`, `sp-cc-17` — the CTRL knobs, named by raw CC number | `m_404`, `[makefilename sp-cc-%d]` | verified | 195 |
| `disp` | `sp-a1 <velocity>` on the press and `sp-a1 0` on the release — one row, updated in place | ⛔ **`u_map`, not this layer** — its raw row for an unmapped control. A pad the current mode maps draws its destination's row instead | verified | 317 |

**One name carries the bank and the pad**, so `sp-a1` and `sp-b1` are told apart on the screen with
nothing beside them.

⚠️ **Every pad is a different name**, and `g_oled`'s param layer holds five rows and refuses a sixth
until one ages out, about 1.3 s after it last moved — so a fast run of pads fills the screen and the
later ones are refused. A playing pattern does the same, because nothing can tell a hand from the
sequencer (items 204 and 205). See [display.md](../module/display.md).

### Trigger rate

| Measure | Value | Evidence | Item |
|---------|-------|----------|------|
| `m_404`'s limit | 5 ms minimum interval = 200/s, about half the device's ceiling (Reference, item 208) | verified | 231 |

5 ms is fifteen times a sixteenth-note stream at 200 BPM. The limiter sits **before** the note-off is
scheduled, so a dropped trigger can never leave an orphan note-off behind it.

### Settings Cut It depends on

The MIDI tab is in Reference. The ones Cut It depends on are **MIDI Mode A**, **Soft Through off**,
**USB-MIDI Thru off** and **MIDI Sync Out off**; the pre-set check is on [rig.md](../rig.md).
### Presence

`m_404` registers as `active` on the presence bus and is polled every two seconds with a universal
device inquiry. **The 404 answers** — manufacturer byte `41`, Roland, item 249 — so `[c_devid 65]`
inside `m_404` is what tells its reply apart from the other two on the one `[sysexin]` the whole
patch shares. ⚠️ **The argument is decimal and the byte is hex**: `41` is 65.

**Both channel gates count as liveness** — the note path and the CTRL knob path — and ⚠️ **a playing
pattern counts too**, which is right rather than a loophole. This page already establishes that a
sequenced note cannot be told from a hand press; presence does not need to. A device that is
transmitting is a device that is plugged in. The inquiry leaves on **port 3**, derived as
`(33-1)/16+1`. See [presence.md](../module/presence.md).

## Traps

Each is a claim and its fix. How any of them was found is in the git history. The device's own traps
(fixed velocity, the bank selected for a receive test, the BPM beside a pad, effect CCs, the dead CC 7
and Program Change, the looping toggle, `MONO (Left)`, charge-only cables) are in Reference.

### `47 + n` is wrong

The pad map breaks that formula at pad 5, which is **44, not 52** (Reference).

⛔ Sequencing code written against it looks correct and triggers the wrong drums with no error.

**Fix:** use the table above. `test/gate/docs-check.py` asserts it against the patch across all sixteen
pads -- a check that samples only pads 1-4 reproduces the mistake.

### The note-off must carry its own channel, and `makenote` cannot

⛔ `[makenote]` -> `[noteout]` is safe for the Volca, which has **one** channel set cold at load. The
404 has **ten**. `makenote` schedules the note-off, and by the time it fires `noteout`'s cold channel
inlet holds whatever the *most recent* event set -- so two banks overlapping within the note duration
send the off to the wrong bank, silently.

**Fix:** carry the channel with the delayed off through `[pipe 0 0 0 200]`, letting `unpack`'s
right-to-left order give cold-then-hot for free. This is what `m_404` does.

### The device's quirks, as they bear on Cut It

- **The effect CCs are playable** (Reference, item 262). **Why it matters:** the 404 is the audio front
  end for the entire rig — every sound passes through it. Real-time effect control from Pd means a
  Launchpad pad or a nano fader can play the 404's DSP as an instrument. ⚠️ **Nothing in
  [plan-v04.md](../../plan-v04.md)'s v0.4 design assumes this is possible**, because until it was
  measured nobody knew it was.
- ⚠️ **CC 7 and Program Change do nothing** (Reference, item 260), and **this costs the instrument
  nothing.** Cut It drives the 404 with notes, and notes are what a cut-up instrument sends: 160
  addressable pads, real velocity, and clock-following BPM sync are all verified and are the whole
  front end. Whatever the menu says belongs on the pre-set checklist either way, because it is a
  setting no cable reveals.
- ⛔ **A looping pad toggles on note-on** (Reference, item 259). **What this means for `m_404`:** the
  `pipe 0 0 0 200` note-off is **harmless** here, because the device ignores it. The hazard is on
  the other side — **any sampler that retriggers a looping pad will silence it instead**, and the
  failure looks like a dropped trigger rather than a toggle.

  ⚠️ **It cannot bite today.** `cut-it-map.txt` maps no control to a 404 pad — tempo, transport and
  one Volca CC are the whole map. **v0.4's sampler is exactly the thing that would hit it**, which is
  why it is written down now. ⛔ **And the easy fix is not available:** "set the pads to one-shot" would
  work, except play mode is set ad hoc during performance (item 263), so the patch cannot assume any
  of them. **Fix:** the sampler has to survive both behaviors. **Track intent, not state** — a
  retrigger that means *restart* has to be sent as stop-then-start when the pad might be looping.
  Whatever v0.4 does here, it cannot be *"we set them all to one-shot once."*

### The rate limit drops, and must never queue

There is no queue between Pd and the 404 (Reference), so an event over the limit is dropped and never
deferred.

**Fix:** a closed `[spigot]` emits nothing, so the event is *gone* rather than deferred. 5 ms
minimum interval, set before the note-off is scheduled so a dropped trigger leaves no orphan.

## Design

### The 404 carries the whole audio split

Hard-panning drums left and fx right turns one stereo pair into two independent mono streams, which
is what lets the Organelle process them separately. **The pan is a per-sample property saved with the
project**, so it recalls — which is why no routing in this rig depends on a knob position.

**Fallback if the per-sample pan is ever unavailable:** export mono samples, or stereo files with one
channel silent. That works, but it bakes the routing into the audio, so changing your mind means
re-exporting. The per-sample pan is reversible and is what this design assumes.

### The mic bleeding into both channels is accepted

The alternative was splitting the mic through the mixer's FX send — more cables, and more unlabelled
knob state to get wrong mid-set.

**The upside is free:** the vocal arrives dry via the drums path and mangled via the fx path at the
same time, which is the standard dry/wet vocal setup.

**The cost:** live vocals are captured into any drums-channel sampler. Sing while Cut It grabs a drum
buffer and your voice is baked into it. Handle it at capture time — a "do not record into drum
buffers" toggle, or simply not arming drum capture while the mic is hot. Cheap now, annoying to
retrofit. Once a vocal is *sampled* to a pad it behaves like any other sample and can be panned hard
right; only live passthrough bleeds.
